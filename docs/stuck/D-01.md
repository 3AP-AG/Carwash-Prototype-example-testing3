## What blocks it

`feature/CAAS-1374-walking-skeleton` and `main` have **unrelated histories**: the branch starts at
its own root commit (`269586a`, a newer template snapshot, 168 files) and `main` starts at
`b8479d5` (an older template snapshot, 125 files). `git merge-base origin/main HEAD` is empty, so
GitHub cannot compare the two and a pull request cannot be opened.

That blocks everything downstream:

- `.github/workflows/pipeline.yml` runs on `pull_request` and on pushes to `main` only, so the
  push to the feature branch (commit `079dcf2`) started no run.
- `.github/rulesets/main.json` requires a pull request plus the `gates` and `path-check` checks on
  `main`, so pushing there directly is neither possible nor intended.
- The `gh` CLI is not installed in the session that built this and no GitHub token was available,
  so the pull request could not be opened from there either.

## One design note

The appointment time travels as a validated `"HH:mm"` string in both directions, not as a
`LocalTime`. A `LocalTime` in the request DTO generates a Zod schema that accepts an empty string,
so an empty time field would fail as an unparseable body (a form-level error) instead of a field
error, which the fourth acceptance bullet requires. The entity still stores a `LocalTime`.
